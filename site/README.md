# PDF·Лимит — тестовый лендинг

Статический сайт без сборки и зависимостей. 4 страницы, 3 файла ассетов.

## Локальный запуск

```bash
cd ~/projects/pdf-limit/site
python3 -m http.server 8099
# открыть http://127.0.0.1:8099/
```

## Что подключить перед публикацией

1. **Яндекс.Метрика.** Создать счётчик, вставить его код в `<head>` каждого файла (шаблон закомментирован в `index.html`), затем выставить `YM_ID` в `app.js` — сейчас там `0`, цели не отправляются.
2. **Цели в Метрике.** Создать цель типа «JavaScript-событие» с идентификатором `pay_click`. Это единственная метрика теста: клик по кнопке оплаты.
3. **Платёжный провайдер.** `pay.html` — заглушка: форма проверяет email и согласие, показывает сообщение, деньги не списываются. Заменить обработчик в `app.js` на редирект к платёжной форме.
4. **Контакты и реквизиты.** `hello@example.com` в футере и в `privacy.html` заменить на реальные. Для модерации Директа нужны сведения о продавце.

## Публикация

Вариант А — GitHub Pages: репозиторий → Settings → Pages → Deploy from branch `main`, папка `/site`.
Вариант Б — любой статический хостинг (Cloudflare Pages, Netlify): корень публикации — папка `site/`.

Домен лучше свой: и для модерации объявлений, и потому что `<login>.github.io` снижает доверие в нише с паспортами.

## Структура

- `index.html` — лендинг: оффер, три провала конкурентов, как работает, лимиты, гарантия, FAQ.
- `pay.html` — экран оплаты (заглушка).
- `privacy.html` — политика (черновик, требует реквизитов).
- `styles.css` — вся вёрстка, адаптив от 360 px, без внешних шрифтов.
- `app.js` — аналитика и поведение формы.

## Проверено

Локально: все внутренние ссылки отдают 200, один `<h1>`, при ширине 360 px горизонтального скролла нет, форма с пустым email не отправляется, с заполненной — показывает подтверждение и блокирует кнопку. Ошибок JS нет.
